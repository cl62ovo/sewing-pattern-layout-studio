# Plush Pattern Studio POC Roadmap

## 1. 目标

将现有的二维纸样排版演示重建为可维护的云端 Web 应用，并验证以下闭环：

> 文字或参考图 -> Meshy 3D 模型 -> 自动接缝与二维展开 -> 几何质量报告 -> 三视图 PNG 与 1:1 A4 PDF -> 布料排版

POC 面向低弹短毛绒的简化单体玩偶，可包含细长耳朵或尾巴。输出必须标记为“实验性纸样”，不得宣称已通过真实布料或实缝验证。

## 2. 成功标准

POC 完成时，用户能够：

1. 使用 Google 登录并创建项目。
2. 输入英文或中文描述、总高度，并可选上传参考图、草图或三视图。
3. 触发一次 Meshy 生成任务，预览 GLB，接受、文字修改或重新生成。
4. 自动得到不超过 12 个裁片；失败时系统自动增加裁片并重算。
5. 查看平均形变、最大形变、缝边长度差、网格修复结果和风险区域。
6. 下载白底正、侧、背正交 PNG，以及带 5 cm 校准方格的 1:1 A4 拼页 PDF。
7. 将生成裁片送入布料尺寸、缝份、方向和省布排版流程。

几何验收门槛：

- 输入网格为闭合、可定向的流形表面，或能被自动修复为该状态。
- 裁片数量不超过 12。
- 面积加权平均二维展开形变不高于 3%。
- 每对缝边的相对长度差不高于 0.5%。
- PDF 中 5 cm 校准方格的矢量尺寸误差不高于 0.2 mm。
- 所有低于门槛的结果默认阻止正式导出；用户只能下载带明显水印的诊断包。

## 3. 范围边界

### POC 包含

- 英文优先、中文切换。
- 纯文字输入；参考图可选；总高度必填。
- Meshy 单供应商，单候选，可重新生成。
- 默认左右对称，可由生成结果表现为非对称。
- 低弹短毛绒材料预设。
- 默认 0.7 cm 缝份，导出前可修改。
- 缝合线、裁剪线、裁片名、数量和镜像标记。
- 数字几何验证、三视图、A4 PDF 和后续省布排版。
- Windows Server 上的 Python 服务和后台任务进程。

### POC 不包含

- 真实布料物理仿真或“保证可缝”承诺。
- 对位刀口、返口、缝制顺序和新手教程。
- 用户在 3D 表面手动画接缝。
- 多模型供应商、多候选并行或平台额度计费。
- 服装、箱包、关节玩偶、复杂孔洞结构。
- 生产级全自动 Blender 集群。

## 4. 开发阶段

### M0：工程重建与风险样例（2-3 天）

交付：

- 建立前端、FastAPI、任务 Worker、数据库迁移和对象存储适配层。
- 建立 `.env.example`，所有外部密钥仅由服务端读取。
- 准备 3 个固定 GLB 样例：圆润单体、带耳朵、带尾巴。
- 保存当前静态站点为视觉和排版行为参考，不在压缩产物上继续开发。

退出条件：

- 本机一条命令分别启动 Web、API 和 Worker。
- 健康检查、数据库连接和对象存储上传通过。
- 密钥不会出现在浏览器包、日志或 Git 变更中。

### M1：项目与生成任务骨架（3-5 天）

交付：

- Google OAuth、用户项目列表、项目详情与版本记录。
- 创建项目表单：描述、总高度、可选参考图。
- 有限状态任务：`draft -> generating -> model_review -> processing -> pattern_review -> ready/failed`。
- 任务进度、取消、重试、幂等键和错误详情。
- Meshy 适配器接口及真实 API 调用。

退出条件：

- 真实输入能生成并保存一个 GLB。
- 刷新页面后任务和项目状态不丢失。
- 同一幂等键不会产生重复计费任务。

### M2：模型规范化与三视图（3-5 天）

交付：

- GLB 下载、病毒/类型/大小检查和隔离存储。
- 网格单位统一、以总高度缩放、坐标轴和朝向规范化。
- 网格诊断：边界边、非流形边、孤立壳、退化面、自交近似检查。
- 基础修复、减面和法线统一。
- 正、侧、背正交 PNG 渲染。

退出条件：

- 3 个风险样例均能产生确定性的规范化网格和三视图。
- 无法修复的网格会给出结构化失败原因，不进入展开阶段。

### M3：自动分片与二维展开技术验证（7-10 天）

交付：

- 对称面估计、凸起区域识别和候选接缝图。
- 从少裁片方案开始，按高曲率/高形变区域逐步增加接缝。
- 每个裁片参数化展开，并保存三维边界到二维边界的对应关系。
- 形变、翻转三角形、边界差和缝边配对指标。
- 最多 12 片和有限重试预算。

退出条件：

- 固定样例满足几何验收门槛。
- 相同输入和算法版本产生可复现结果。
- 失败结果明确指出网格、分片、展开或阈值失败。

### M4：纸样 PDF 与质量报告（4-6 天）

交付：

- 生成缝合线和偏置后的裁剪线。
- 添加裁片名、数量、镜像、总高度、比例、版本与实验性水印。
- A4 自动拼页、页码、拼接边和 5 cm 校准方格。
- 2D/3D 对应着色预览和风险区域报告。
- 合格导出与不合格诊断包分流。

退出条件：

- PDF 使用矢量路径，不以低分辨率位图代替纸样。
- 自动测试验证页尺寸、校准方格、缝份距离和跨页坐标。
- 打印设置明确要求 100% / Actual size。

### M5：接回省布排版（5-8 天）

交付：

- 将裁片从位图遮罩升级为真实二维多边形/曲线路径。
- 支持布料宽长、裁片数量、镜像、毛向和允许旋转规则。
- 使用真实轮廓加缝份进行碰撞，而不是外接矩形。
- 输出裁剪排版预览与利用率。

退出条件：

- 最终布局不存在轮廓重叠或越界。
- 毛向固定时不得出现 180 度倒置。
- 同一纸样 PDF 与排版器使用同一套毫米坐标数据。

### M6：Windows Server 部署与 POC 验收（3-5 天）

交付：

- Web/API/Worker 以 Windows 服务运行，反向代理启用 HTTPS。
- PostgreSQL、对象存储、任务队列、日志轮转和备份。
- 每用户限流、上传限制、任务超时、API 预算和管理员诊断页。
- 端到端测试：纯文字、参考图、重生成、失败修复、PDF 和排版。

退出条件：

- 连续完成 10 次受支持输入，任务不会卡死或重复扣费。
- 单任务目标耗时 3-8 分钟，外部 API 成本保持在约 ¥5-15。
- 服务重启后未完成任务可恢复或安全失败。

## 5. 优先级

### P0：必须先证明

- Meshy 输出是否能稳定得到可修复的封闭网格。
- 自动分片能否在 12 片内将平均展开形变控制到 3%。
- 三维缝边和二维边界能否保持可靠对应。
- A4 PDF 是否保持真实毫米尺寸。

### P1：形成完整产品闭环

- Google 登录与云端项目。
- 模型审阅、文字修改、任务历史。
- 质量报告和省布排版。

### P2：POC 后再评估

- 对位刀口、返口和缝制顺序。
- 用户手工编辑接缝。
- Blender/布料物理仿真。
- 多供应商、平台计费和团队协作。

## 6. 开发启动顺序

第一周不要先做完整界面。建议按以下顺序开工：

1. 用固定 GLB 建立 `normalize -> segment -> flatten -> score -> PDF` 命令行管线。
2. 让三个风险样例通过或得到可解释失败。
3. 再接 Meshy 真实输出，统计网格失败类型。
4. 管线稳定后接入 FastAPI 任务和对象存储。
5. 最后重建前端工作流并接回排版器。

若 M3 无法达到退出条件，应暂停产品功能开发，先收紧允许造型范围或引入 Blender/更成熟的几何库，不应通过放宽质量阈值掩盖失败。
