# Plush Pattern Studio：当前真实问题与改进方向

> 用途：PPT 内容素材。本文只记录截至 2026-08-02 在真实运行、自动测试和浏览器验收中能够被证据支持的问题，不把已经修复的问题继续描述为当前缺陷。

---

## 1. 一句话结论

原型已经打通“文字需求 → 3D 模型 → 规范化 → 分片 → 展开 → 评分 → SVG/PDF”的技术链路，但**真实生成模型目前仍无法稳定达到可打印纸样的质量门槛**。

当前最大的风险不在页面或 API，而在 3D 生成质量和自动展开算法之间的断层：系统能够识别失败并阻止错误 PDF，但还不能把当前真实 Cloud Rabbit 模型自动修正为合格纸样。

**PPT 可用表述：**

> We built the full pipeline, but a complete pipeline is not the same as a production-ready pattern. The current prototype can reject unsafe geometry correctly; the next challenge is making real generated meshes pass.

---

## 2. 当前原型已经做到什么

- React 工作台、FastAPI、独立 Worker、本地数据库和对象存储已接通。
- 能处理 `normalize → segment → flatten → score → PDF` 全流程。
- 合格样例可生成带 50 mm 校准框的 A4 矢量 PDF。
- 不合格样例只生成诊断 SVG 和质量 JSON，自动阻止 PDF。
- 质量门槛是确定性的，不由 LLM 决定：
  - 裁片数不超过 12。
  - 平均形变不超过 3%。
  - 配对缝边误差不超过 0.5%。
  - 翻转三角形、自交和未配对缝边必须为 0。
- 当前自动验证结果：后端 18 项、前端 3 项测试通过，生产构建成功。

**不要在 PPT 中说：**“系统已经可以把任意 3D 玩偶自动变成可缝制纸样。”

**更准确的说法：**“系统已经具备完整的生成、验证和失败分流能力。”

---

## 3. P0：真实模型没有通过展开质量门槛

当前真实项目 `Cloud Rabbit MVP` 已完成 12 片分片，但最终质量报告为失败，因此没有生成 PDF。

| 指标 | 验收门槛 | 当前实测 | 结果 |
|---|---:|---:|---|
| 裁片数 | ≤ 12 | 12 | 达到上限 |
| 平均形变 | ≤ 3% | 219.89% | 严重失败 |
| 最大局部形变 | 风险提示 | 8952.13% | 极端异常 |
| 缝边误差 | ≤ 0.5% | 约 0.000027% | 通过 |
| 翻转三角形 | 0 | 419 | 失败 |
| 边界自交 | 0 | 5 | 失败 |
| 未配对缝边 | 0 | 0 | 通过 |
| PDF | 全部门槛通过才生成 | 未生成 | 正确阻止 |

失败代码：

- `FLATTENING_FLIPPED_TRIANGLES`
- `FLATTENING_DISTORTION_TOO_HIGH`

这说明缝边配对和长度同步已经有效，但二维展开本身仍不可靠。当前算法为了压到 12 片而合并过多区域，可能形成不适合单片展开的复杂曲面。

**用户影响：**

- 用户能看到诊断纸样，但不能得到正式 PDF。
- 轮廓看起来像“纸样”并不代表可以裁剪或缝制。
- 如果取消质量门强行导出，会制造尺寸错误和不可缝合风险。

**改进方向：**

1. 不降低 3% 和 0.5% 门槛。
2. 在高形变区域自动增加或移动接缝，而不是只做图表合并。
3. 将失败三角形定位回 3D 模型，在 2D/3D 中同步高亮。
4. 允许算法在“超过 12 片”和“无法安全展开”之间给出明确建议。
5. 对耳朵、尾巴、细颈等凸起使用部件级分片策略。

**PPT 标题建议：**“The pipeline works, but the real pattern fails safely.”

## 4. P0：上游 AI 生成网格不适合直接制版

当前真实 Meshy 原始模型的拓扑质量很差：

| 原始输入诊断 | 当前实测 |
|---|---:|
| 顶点数 | 17,451 |
| 面数 | 20,807 |
| 连通组件 | 1,418 |
| 边界边 | 11,591 |
| 是否封闭 | 否 |
| 是否绕序一致 | 是 |

旧版 192 分辨率体素修复虽然把模型变成封闭单体，却把网格扩大到 172,864 个三角形，导致分片阶段耗时过长。当前 `normalize-v3` 已改为有界的 64 分辨率修复，并在 `pattern-v3` 中兼容旧高密度资产，但这只能改善性能和拓扑，不能保证展开质量。

**根本矛盾：**

- Meshy 优先生成视觉上合理的表面。
- 制版需要封闭、低噪声、可分片、长度可信的几何。
- “看起来像玩偶”与“适合生成纸样”是两个不同目标。

**改进方向：**

1. 收紧生成提示和支持造型范围，优先单体、低曲率、低细节模型。
2. 在接受模型前显示拓扑风险，而不只显示外观预览。
3. 对生成供应商输出建立面数、连通壳、边界边和细颈阈值。
4. 评估更适合制造几何的生成方式，或加入 Blender/专用重拓扑步骤。
5. 保存修复前后对比图，帮助用户理解“视觉成功但工程失败”。

**PPT 可用表述：**

> Generative 3D optimizes appearance. Pattern making requires manufacturable topology.

## 5. P0：真实样本验证数量不足

当前自动测试覆盖：

- 1 个盒体。
- 3 个合成风险样例：rounded body、long ears、simple tail。
- 这些固定样例均能通过质量门。

但当前接入的真实 Cloud Rabbit 模型没有通过。也就是说，**测试证明算法能处理受控网格，但尚未证明它能稳定处理真实供应商输出**。

**现有证据缺口：**

- 没有连续 10 次真实生成验收数据。
- 没有不同提示、不同随机种子、不同体型的通过率。
- 没有统计各失败类型的占比。
- 没有平均耗时、P95 耗时和单次外部 API 成本基线。

**建议验收集：**

- 10 个简单圆身体。
- 10 个带耳朵模型。
- 10 个带尾巴模型。
- 每类记录：生成成功率、修复成功率、≤12 片成功率、质量通过率、总耗时和成本。

**PPT 标题建议：**“Synthetic tests pass; real-world reliability is still unproven.”

## 6. P1：数字几何通过不等于真实可缝

当前系统验证的是数字几何，不是完整缝纫工艺。

尚未完成或未经过实物验证的内容：

- 对位刀口。
- 返口位置。
- 缝制顺序。
- 省道和局部收褶。
- 毛向、布纹方向和材料伸缩率。
- 左右镜像及裁片数量的工艺语义。
- 接缝交汇处的装配合理性。
- 打印、拼页、裁剪和实物缝制闭环。

即使未来某个模型通过 3%/0.5% 数字门槛，也只能说明它满足当前算法定义，不能直接证明成品可缝、好缝或外形正确。

**必须补充的验证：**

1. 选择 3 个最简单的通过样例进行 100% 比例打印。
2. 实际裁剪和缝制。
3. 记录对位误差、返工点、成品尺寸和外形偏差。
4. 由有经验的纸样师评审接缝布局。

**PPT 可用表述：**

> Geometry validation reduces risk; it does not replace a physical sewing test.

---

## 7. P1：纸样生成与省布排版仍是两个系统

当前主工作台中的 `Nest & Cut` 仍通过旧版 iframe 加载。它可以作为排版演示，但尚未真正消费 `pattern-v3` 生成的毫米级多边形数据。

**当前问题：**

- 纸样生成器和排版器没有共享同一份权威坐标数据。
- 排版器尚未证明使用真实裁剪轮廓和缝份做碰撞。
- 毛向、镜像、允许旋转角度和裁片数量规则尚未贯通。
- 无法证明排版结果不存在真实轮廓重叠或越界。

**改进方向：**

1. 用共享 contract 将 `PatternPiece.cutPathMm` 直接传给排版器。
2. 移除 iframe，改为同一 React 应用内的真实模块集成。
3. 使用真实多边形碰撞，而不是位图或外接矩形。
4. 输出布料利用率、排版长度和规则违规信息。

**PPT 标题建议：**“Pattern generation and fabric nesting are connected in UI, not yet in geometry.”

---

## 8. P1：失败诊断对开发者可用，对普通用户仍不够清楚

当前页面能显示质量指标和错误代码，但用户很难理解：

- 哪一块裁片发生了翻转。
- 形变集中在哪个身体部位。
- 为什么 219.89% 代表不可用。
- 应该修改文字描述、重新生成模型，还是调整接缝。

Worker 对部分非预期 `ValueError` 仍会统一映射为 `PROVIDER_ASSET_INVALID`，且没有持久化具体异常消息。这会把“尺寸偏差”“内部数据错误”等不同问题压缩成同一个泛化错误，增加排障成本。

**改进方向：**

1. 为每个错误提供用户可执行的下一步。
2. 在 3D 和 2D 视图中定位风险区域。
3. Worker 保存结构化错误详情、阶段、算法版本和堆栈摘要。
4. 区分供应商资产错误、修复错误、分片错误、展开错误和系统内部错误。
5. 增加管理员任务诊断页。

---

## 9. P1：移动端可用，但工作流过长

390 × 844 移动视口验收中没有发现横向溢出或控件重叠，但完整质量页很长：指标、错误、下载、SVG 预览和 7 步进度全部纵向排列。

**实际体验问题：**

- 用户需要长距离滚动才能看到完整结果。
- 超大 SVG 预览占据大量页面长度。
- 失败原因使用工程错误码，认知成本高。
- 纸张和尺寸参数缺少常用预设。

**改进方向：**

- 移动端将指标折叠为摘要和详情。
- SVG 使用固定高度查看器，支持缩放和全屏。
- 提供 A4、Letter、A3 等纸张预设。
- 用自然语言解释失败，同时保留技术代码供诊断。
- 将主要下一步固定在底部操作栏。

---

## 10. P2：目前仍是本地开发原型，不是生产服务

当前运行形态是本地 React、FastAPI、Worker、本地数据库和本地对象存储。

尚未完成生产化验证：

- Google 登录和真实多用户隔离。
- PostgreSQL、正式对象存储和独立任务队列。
- HTTPS、反向代理和 Windows 服务部署。
- 并发限制、上传限制、任务超时和 API 预算控制。
- 日志轮转、监控、备份和灾难恢复。
- 外部供应商重试、限流和成本告警。
- 服务重启后的系统化恢复测试。

另外，前端生产构建仍有约 957 kB 的 Three.js `ModelViewer` chunk 警告。它不影响当前功能，但会影响首次加载性能，后续应进一步拆包或按需加载。

**PPT 标题建议：**“Validated local prototype, not yet an operational production service.”

## 11. 问题优先级矩阵

| 优先级 | 问题 | 为什么重要 | 下一步 |
|---|---|---|---|
| P0 | 真实模型展开失败 | 当前真实项目没有 PDF | 高形变区域自动加缝、部件级分片 |
| P0 | AI 网格拓扑差 | 输入不封闭且碎片极多 | 收紧输入、重拓扑、供应商质量门 |
| P0 | 真实样本不足 | 无法估计成功率 | 建立 30 个真实模型验收集 |
| P1 | 未做实物缝制 | 数字通过不代表可制造 | 打印、裁剪、缝制 3 个样例 |
| P1 | 排版器仍是旧 iframe | 尚未形成真实省布闭环 | 共享毫米多边形并移除 iframe |
| P1 | 失败解释不直观 | 用户不知道如何修复 | 2D/3D 风险定位和操作建议 |
| P1 | 移动页过长 | 结果阅读效率低 | 折叠指标和固定预览区域 |
| P2 | 未生产化部署 | 无法安全支持真实用户 | 队列、鉴权、监控、备份 |
| P2 | 3D chunk 较大 | 首屏性能风险 | 继续懒加载和拆包 |

## 12. 建议下一阶段目标

### 第一阶段：证明真实模型能通过

- 固定 10 个最简单的真实生成模型。
- 实现高形变区域自动补缝。
- 将真实通过率提升到可量化水平。
- 不通过时给出可执行的重生成建议。

### 第二阶段：证明纸样真的能缝

- 打印 3 套通过质量门的 PDF。
- 完成实物裁剪和缝制。
- 根据实际偏差修正数字门槛和纸样标注。

### 第三阶段：接通真实省布排版

- 让排版器直接消费 `cutPathMm`。
- 验证轮廓碰撞、毛向、镜像和数量规则。
- 输出真实布料利用率。

### 第四阶段：生产化

- 多用户、正式队列、数据库和对象存储。
- 监控成功率、耗时、外部 API 成本和失败类型。
- 完成连续 10 次任务和服务重启恢复验收。

## 13. PPT 可直接使用的关键数字

- `12 / 12`：当前真实模型已经用满裁片预算。
- `219.89%`：平均展开形变，门槛为 3%。
- `419`：翻转三角形数量，门槛为 0。
- `5`：边界自交数量，门槛为 0。
- `0.000027%`：缝边误差，门槛为 0.5%，该部分表现良好。
- `1,418`：真实原始网格的连通组件数量。
- `11,591`：真实原始网格的边界边数量。
- `172,864`：旧高分辨率修复后的三角形数量。
- `18 + 3`：当前通过的后端和前端自动测试数量。
- `957 kB`：当前 Three.js 模型查看器生产 chunk 大小。

## 14. 推荐 PPT 叙事顺序

1. **Problem**：传统排版浪费时间和布料，新手难以把创意变成纸样。
2. **Prototype**：展示完整技术链路和可运行界面。
3. **What works**：自动分片、评分、诊断 SVG、合格 PDF 和安全门控。
4. **Real test**：展示 Cloud Rabbit 的真实质量数据。
5. **Main insight**：视觉上成功的 AI 3D 模型不等于可制造几何。
6. **Responsible behavior**：系统没有强行导出错误 PDF，而是阻止并解释失败。
7. **Current gaps**：真实成功率、实物缝制、排版集成和生产部署。
8. **Next steps**：真实数据集、智能补缝、实物验证、统一排版。
9. **Closing**：原型已经证明闭环可实现，下一阶段要证明它稳定、可缝、可规模化。
